## Описание реализации и проверки

### `row_sums` (Суммы строк)

Функция принимает матрицу и возвращает список сумм по каждой строке. Для пустой матрицы возвращает `[]`.

**Проверки:**

| Вход | Ожидаемый результат |
|------|---------------------|
| `[[1, 2, 3], [4, 5, 6]]` | `[6, 15]` |
| `[[7]]` | `[7]` |
| `[[1], [-1], [0]]` | `[1, -1, 0]` |
| `[]` | `[]` |

---

### `column_sums` (Суммы столбцов)

Функция возвращает список сумм по каждому столбцу. Сначала создаётся список нулей длиной, равной количеству столбцов (`len(matrix[0])`), затем по каждому столбцу суммируются значения всех строк. Длина строки берётся реальная (`len(matrix[0])`), а не предполагается квадратная таблица. Для пустой матрицы возвращает `[]`.

**Проверки:**

| Вход | Ожидаемый результат |
|------|---------------------|
| `[[1, 2, 3], [4, 5, 6]]` | `[5, 7, 9]` |
| `[[7]]` | `[7]` |
| `[[1], [-1], [0]]` | `[0]` (один столбец) |
| `[]` | `[]` |

---

### `diagonal_pattern` (Диагональный узор)

Функция создаёт квадратную таблицу `size × size`:
- на главной диагонали (`row == column`) — `0`,
- выше диагонали (`row < column`) — `1`,
- ниже диагонали (`row > column`) — `2`.

Таблица создаётся через `[[0 for _ in range(size)] for _ in range(size)]` — каждое значение строится отдельным внутренним списком, поэтому все строки независимы.

**Проверки:**

| size | Ожидаемый результат |
|------|---------------------|
| 1 | `[[0]]` |
| 3 | `[[0, 1, 1], [2, 0, 1], [2, 2, 0]]` |

Узор размера 3 в виде таблицы:

```
0 1 1
2 0 1
2 2 0
```

### `main.py` (Интерактивный ввод таблицы)

Программа работает в три шага:

1. **Ввод прямоугольной матрицы.** Запрашивается количество строк и столбцов (оба положительные, повтор ввода при некорректном значении). Каждая строка вводится через пробел; если количество значений не совпадает с заданным числом столбцов, строка запрашивается повторно.
2. **Суммы.** Выводятся исходная таблица, суммы строк и суммы столбцов. Перед вычислениями создаётся снимок `snapshot = [row.copy() for row in table]`, после вызовов проверяется `assert snapshot == table` — функции не меняют полученную матрицу.
3. **Диагональный узор.** Запрашивается положительный размер, выводится узор.

### Индивидуальный вариант 15: Ненулевые элементы заменить знаком: 1 или -1

Функция `transform(matrix)` возвращает новую матрицу той же формы:
- положительные элементы заменяются на `1`,
- отрицательные — на `-1`,
- нули сохраняются.

Для `[]` результат — `[]`.

**Контрольная матрица:** `[[-2, 0, 3], [4, -5, 6]]`  
**Ожидаемый результат:** `[[-1, 0, 1], [1, -1, 1]]`

Функция сначала создаёт независимую копию таблицы `[r.copy() for r in matrix]`, а затем меняет значения в копии. Исходная матрица остаётся без изменений.

**Проверки:**

| Вход | Результат |
|------|-----------|
| `[[-2, 0, 3], [4, -5, 6]]` | `[[-1, 0, 1], [1, -1, 1]]` |
| `[]` | `[]` |
| Изменение `result[0][0] = 999` в результате | Исходная матрица не изменилась: `control_matrix[0][0] == -2` |

### Дополнительный модуль: рекурсия

В `table.py` реализованы две версии факториала:

- `factorial(number)` — рекурсивная: базовый случай `number == 0` возвращает `1`, иначе `number * factorial(number - 1)` — шаг приближает к базовому случаю.
- `factorial_iterative(number)` — итеративная: произведение накапливается в цикле.

Результаты обеих функций совпадают для чисел 0–20.

**Проверки:**

| Вызов | Ожидаемый результат |
|-------|---------------------|
| `factorial(0)` | `1` |
| `factorial(5)` | `120` |
| `factorial(5)` и `factorial_iterative(5)` | оба равны `120` |

**Трассировка `factorial(3)`:**
- вызовы: `factorial(3)` → `factorial(2)` → `factorial(1)` → `factorial(0)`;
- возвраты: `1` → `1` → `2` → `6`.

Предел глубины рекурсии не увеличивается: слишком глубокая цепочка вызовов вызывает `RecursionError`.

## Пояснения по ключевым темам (для защиты работы)

- **Строки и столбцы в матрице:**  
  В `matrix[row][column]` первый индекс задаёт строку, второй — столбец. Например, `[[1, 2, 3], [4, 5, 6]]` содержит две строки и три столбца. Для вычислений используется реальная длина строки (`len(matrix[0])`), а не предположение о квадратности таблицы.

- **Почему нельзя создавать таблицу как `[[0] * columns] * rows`:**  
  Все элементы внешнего списка будут ссылаться на один и тот же внутренний список. Изменение одной ячейки, например `matrix[0][0] = 7`, затронет сразу все строки — в каждой из них первый элемент станет равным 7. Правильный способ — списковое включение: `[[0] * columns for _ in range(rows)]`, где каждая строка создаётся заново.

- **Чем `matrix.copy()` отличается от копирования строк:**  
  `matrix.copy()` копирует только внешний список: в нём лежат ссылки на те же самые строки. Изменение элемента любой строки будет видно и в «копии», и в исходной таблице. Для независимой копии таблицы чисел используют `[row.copy() for row in matrix]` — каждая строка копируется отдельно. Именно это сделано в `transform()` и в снимке `snapshot` в `main.py`.

- **Какую ошибку выявляет таблица 2×3:**  
  Неквадратная таблица проверяет, что код не опирается на предположение «число строк равно числу столбцов». Суммы строк (их две) и суммы столбцов (их три) считаются по реальным размерам: `len(matrix)` и `len(matrix[0])`. Если бы код строил суммы столбцов по длине внешнего списка, результат был бы неверным.

- **Функции не меняют исходную матрицу:**  
  `row_sums`, `column_sums` и `diagonal_pattern` только читают данные и создают новые списки. `transform` работает с независимой копией строк. Это подтверждается проверками: после всех вызовов исходная матрица равна своему снимку, а изменение результата `transform` не затрагивает контрольную матрицу.
