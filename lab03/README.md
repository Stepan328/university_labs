## Описание реализации и проверки

### `minimum.py` (Минимум трёх чисел)

Программа вводит три целых числа и находит минимальное через `if/elif/else`. Функции `min`, `max` и сортировка не используются — цель: потренировать ветвление. Равные числа допускаются.

**Логика:**
- Сначала сравниваются первое и второе число.
- Затем результат сравнивается с третьим.
- Если равны — выводится это значение (корректно, так как минимум равных чисел равен им самим).

**Проверки:**

| Вход | Ожидаемый результат | Фактический результат |
|------|---------------------|----------------------|
| 2, 10, 3 | 2 | 2 |
| 5, 5, 5 | 5 | 5 |
| -4, 0, -2 | -4 | -4 |
| 7, 3, 1 | 1 | 1 |

Дополнительная проверка: случай, когда минимум на последней позиции (7, 3, 1 → 1).

### `calculator.py` (Калькулятор)

Программа вводит два вещественных числа и строку с одной операцией: `+`, `-`, `*`, `/`. Результат выводится с двумя знаками после запятой. При делении на ноль выводится сообщение об ошибке, при неизвестной операции — сообщение «Неизвестная операция». `eval()` не используется.

**Проверки:**

| Вход | Ожидаемый результат | Фактический результат |
|------|---------------------|----------------------|
| 7, 2, / | 3.50 | 3.50 |
| 5, 0, / | Деление на ноль запрещено | Деление на ноль запрещено |
| 5, 2, ? | Неизвестная операция | Неизвестная операция |
| 10, 3, + | 13.00 | 13.00 |
| 10, 3, - | 7.00 | 7.00 |
| 4, 2.5, * | 10.00 | 10.00 |

### `point.py` (Принадлежность прямоугольнику)

Программа вводит координаты `x`, `y`. Прямоугольник задан условиями `0 <= x <= 5` и `0 <= y <= 3`. Граница включена. Выводится «Внутри или на границе» либо «Снаружи».

**Логика:**
- Используется составное условие с `and`: `0 <= x <= 5 and 0 <= y <= 3`.
- Если условие истинно — точка внутри или на границе, иначе — снаружи.

**Проверки:**

| Вход (x, y) | Ожидаемый результат | Фактический результат |
|-------------|---------------------|----------------------|
| 2, 2 | Внутри или на границе | Внутри или на границе |
| 5, 3 | Внутри или на границе | Внутри или на границе |
| 5.1, 3 | Снаружи | Снаружи |
| 0, 0 | Внутри или на границе | Внутри или на границе |
| -1, 1 | Снаружи | Снаружи |

### `variant.py` (Вариант 15: Заполнение архива)

Программа вводит целое число от 0 до 100. При выходе за диапазон выводится «Ошибка диапазона». Иначе определяется категория по таблице:

| Диапазон | Категория |
|----------|-----------|
| 0–44 | Есть место |
| 45–94 | Архив растёт |
| 95–100 | Почти заполнен |

**Логика:**
- Сначала проверяется `if 0 <= number <= 44` — «Есть место».
- Затем `elif 45 <= number <= 94` — «Архив растёт».
- Затем `95 <= number <= 100` — «Почти заполнен» 
- Затем `else` — вывод «Ошибка диапазона».

**Проверки:**

| Вход | Ожидаемый результат | Фактический результат |
|------|---------------------|----------------------|
| -1 | Ошибка диапазона | Ошибка диапазона |
| 0 | Есть место | Есть место |
| 44 | Есть место | Есть место |
| 45 | Архив растёт | Архив растёт |
| 94 | Архив растёт | Архив растёт |
| 95 | Почти заполнен | Почти заполнен |
| 100 | Почти заполнен | Почти заполнен |
| 101 | Ошибка диапазона | Ошибка диапазона |

Проверены значения непосредственно до и после каждого порога: 43, 44, 45, 94, 95.

### `dopolnitelno.py` (Дополнительное задание: Високосный год)

Программа вводит целое число от 1 до 9999 и определяет, является ли год високосным по правилам григорианского календаря:
- Год делится на 400 — високосный.
- Год делится на 4, но не на 100 — високосный.
- Остальные годы — невисокосные.

**Логика:**
- Условие: `year % 400 == 0 or (year % 4 == 0 and year % 100 != 0)`.
- Используется `or` для объединения двух правил и `and` + `not` для второго правила.

**Проверки:**

| Вход | Ожидаемый результат | Фактический результат |
|------|---------------------|----------------------|
| 1900 | Нет | Нет |
| 2000 | Да | Да |
| 2024 | Да | Да |
| 2023 | Нет | Нет |

**Объяснение:**
- 1900 делится на 100, но не на 400 — не високосный.
- 2000 делится на 400 — високосный.
- 2024 делится на 4 и не на 100 — високосный.
- 2023 не делится на 4 — не високосный.

## Пояснения по ключевым темам (для защиты работы)

- **Выбор `and` / `or`:** `and` используется, когда должны выполняться оба условия одновременно (например, точка внутри прямоугольника: `0 <= x <= 5 and 0 <= y <= 3`). `or` — когда достаточно одного из условий (например, проверка выхода за диапазон: `number < 0 or number > 100`).
- **Порядок ветвей в `if/elif/else`:** выполняется только первая подходящая ветвь. Поэтому проверки идут от частного к общему: сначала ошибка диапазона, затем конкретные интервалы. Если бы вместо `elif` использовались отдельные `if`, могло бы выполниться несколько блоков за один запуск.
- **Поведение при равенстве значений:** при равных числах в `minimum.py` сравнение `a <= b` истинно, поэтому любое из равных значений корректно выбирается как минимум. В `variant.py` границы интервалов включены, поэтому значение 44 попадает в «Есть место», а 45 — в «Архив растёт».
