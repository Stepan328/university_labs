## Описание реализации и проверки

### Задание 1: Частоты слов (`word_counts`)

Функция принимает текст и возвращает словарь «слово → количество».

Логика:
1. `text.lower()` — приведение к нижнему регистру.
2. `.split()` — разбиение по пробельным символам.
3. `word.strip(".,!?;:")` — удаление знаков препинания с краёв каждого слова.
4. Пропуск пустых результатов (`if not word: continue`).
5. Подсчёт через `result.get(word, 0) + 1`.

Пары выводятся по алфавиту отдельной функцией `alphabet_sort(totals)` через `for word in sorted(totals)`.

**Проверки:**

| Вход | Ожидаемый результат |
|------|---------------------|
| `"Python, python! SQL"` | `{"python": 2, "sql": 1}` |
| `"!!!"` | `{}` |
| `""` | `{}` |

### Задание 2: Учебные интересы (`common_topics`, `all_topics`)

Аргументы — списки строк (темы уже в нижнем регистре). Используются множества:

- `common_topics(first, second)` — пересечение: `sorted(set(first) & set(second))`.
- `all_topics(first, second)` — объединение: `sorted(set(first) | set(second))`.

Множества автоматически убирают дубли («python» встречается в списке дважды), а `sorted()` даёт воспроизводимый порядок, потому что у множества нет гарантированного порядка вывода.

**Проверки:**

| first | second | Общие | Все |
|-------|--------|-------|-----|
| `["python", "sql", "python"]` | `["sql", "git"]` | `["sql"]` | `["git", "python", "sql"]` |
| `[]` | `["sql", "git"]` | `[]` | `["git", "sql"]` |

### Задание 3: Запись и пара

Создаётся словарь `{"title": "Python", "hours": 10}`, затем:
- изменяется значение существующего ключа: `table['hours'] = 13`,
- добавляется новый ключ: `table['completed'] = False`,
- создаётся кортеж `data = (table['title'], table['hours'])`,
- кортеж распаковывается: `title, hours = data` и выводится на экран.

**Почему запись удобно представить словарём:**

- Поля записи имеют понятные имена: `record["title"]` читается лучше, чем `record[0]`.
- Поля можно добавлять и изменять по мере необходимости (`completed` появился после создания записи).
- Порядок полей не важен, важны имена — при передаче записи в функцию не нужно помнить, что на каком месте стоит.
- Быстрый доступ к значению по ключу без перебора.

Кортеж же удобен как неизменяемая пара значений: его нельзя случайно изменить, и его удобно распаковать в две переменные одной строкой (`title, hours = data`). Тот же механизм работает при переборе словаря: `for key, value in dictionary.items()` — это распаковка пары.

**Проверка:**

| Действие | Результат |
|----------|-----------|
| Создание и изменение словаря | `{'title': 'Python', 'hours': 13, 'completed': False}` |
| Распаковка кортежа | `title = Python`, `hours = 13` |

### Индивидуальный вариант 15: Фотоколлекция

Предметная область — фотоколлекция, поле `amount` — количество снимков в записи.

```python
records = [
    {"title": "Закат у реки", "category": "пейзаж", "amount": 12},
    {"title": "Горные вершины", "category": "пейзаж", "amount": 18},
    {"title": "Улицы старого города", "category": "город", "amount": 10},
    {"title": "Фасады домов", "category": "город", "amount": 5},
    {"title": "Семейный портрет", "category": "портрет", "amount": 8}
]
```

В наборе 5 содержательных записей, три категории, категория «пейзаж» и «город» повторяются.

- `totals_by_category(records)` — словарь сумм `amount` по категориям. Сумма накапливается через `total.get(category, 0) + amount`, исходный список не изменяется.
- `titles_in_category(records, category)` — названия записей заданной категории в исходном порядке. Неизвестная категория даёт `[]`.
- После вызовов функции исходные записи равны копии `[i.copy() for i in records]` — значения записей простые (строки и числа), поэтому поверхностного копирования достаточно.

**Проверки:**

| Вызов | Ожидаемый результат |
|-------|---------------------|
| `totals_by_category(records)` | `{"пейзаж": 30, "город": 15, "портрет": 8}` |
| `totals_by_category([])` | `{}` |
| `titles_in_category(records, "пейзаж")` | `["Закат у реки", "Горные вершины"]` |
| `titles_in_category(records, "нет")` | `[]` |
| `titles_in_category([], "пейзаж")` | `[]` |
| Список после вызовов функций | равен копии исходных записей |

Интерактивная часть: сводка выводится по алфавиту через `sorted(totals)`, затем пользователь вводит категорию (ввод приводится к нижнему регистру через `.strip().lower()`), и выводятся найденные названия. Неизвестная категория даёт `[]` и сообщение «ничего не найдено».

### Дополнительное задание: сортировка пар (`get_sorted`)

Функция возвращает список пар `(category, total)`, отсортированный сначала по убыванию суммы, затем по названию категории:

```python
return sorted(result, key=lambda x: (-x[1], x[0]))
```

- `-x[1]` — минус перед суммой даёт сортировку по убыванию.
- `x[0]` — при равных суммах порядок определяется алфавитным порядком названия категории.

**Проверка:**

| Вызов | Ожидаемый результат |
|-------|---------------------|
| `get_sorted(records)` | `[("пейзаж", 30), ("город", 15), ("портрет", 8)]` |

## Пояснения по ключевым темам (для защиты работы)

- **Выбор структуры данных для каждого задания:**  
  Задание 1 — словарь, потому что нужен счётчик «слово → количество» с быстрым доступом по ключу.  
  Задание 2 — множества, потому что нужны уникальные элементы и операции пересечения/объединения.  
  Задание 3 — словарь для записи (именованные поля) и кортеж для неизменяемой пары значений.  
  Индивидуальный вариант — список словарей: каждая запись это отдельный словарь с одинаковым набором ключей.

- **Поведение `.get()`:**  
  `record["title"]` требует существующего ключа — при его отсутствии возникает ошибка `KeyError`.  
  `record.get("hours", 0)` возвращает значение по ключу, а если ключа нет — указанный запасной результат (здесь `0`). Это удобно для накопления сумм и счётчиков: не нужна предварительная проверка `if key in dict`. Присваивание по существующему ключу заменяет значение (`table['hours'] = 13`).

- **Почему множество сортируется перед выводом:**  
  У множества нет индексов и гарантированного порядка вывода — при каждом запуске порядок может отличаться. Чтобы результат был воспроизводимым (одинаковым в тестах и при проверке), множество переводится в отсортированный список через `sorted()`. Пустое множество создаётся через `set()`, потому что `{}` — это пустой словарь.

- **Почему исходные записи не изменяются:**  
  `totals_by_category` и `titles_in_category` только читают значения (`record["category"]`, `record["amount"]`, `record["title"]`) и собирают новый словарь или список. Ни присваиваний по элементам списка, ни изменений словарей записей нет, поэтому исходные данные остаются без изменений — это подтверждается сравнением с копиями после всех вызовов.
