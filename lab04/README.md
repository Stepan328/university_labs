## Описание реализации и проверки

### `range_numbers.py` (Диапазон в обе стороны)

Программа вводит целые `a` и `b`. Выводит все числа от `a` до `b` включительно: по возрастанию при `a < b`, по убыванию при `a > b`, одно число при равенстве. Каждое число — на отдельной строке.

**Логика:**
- Если `a < b`: `range(a, b + 1)`
- Если `a > b`: `range(a, b - 1, -1)`
- Если `a == b`: достаточно вывести `a` (или `range(a, a + 1)`)

**Проверки:**

| Вход (a, b) | Ожидаемый результат |
|-------------|---------------------|
| 2, 4 | 2<br>3<br>4 |
| 4, 2 | 4<br>3<br>2 |
| 3, 3 | 3 |

---

### `statistics.py` (Статистика потока)

Программа запрашивает целое `n >= 1`, затем ровно `n` целых чисел. Находит: сумму, количество положительных значений, максимум. Списки не используются. Максимум инициализируется первым введённым значением.

**Логика:**
- Счётчик итераций: от 0 до `n-1`.
- Накопитель суммы: `sum_numbers += chis`.
- Счётчик положительных: `if chis > 0:
        count_positive += 1`.
- Максимум: `maximum = -10**1000` и обновление при `chis > maximum`.

**Проверки:**

| Вход | Ожидаемый результат |
|------|---------------------|
| n=3, числа -5, -2, -8 | Сумма: -15, положительных: 0, максимум: -2 |
| n=1, число 0 | Сумма: 0, положительных: 0, максимум: 0 |

---

### `positive_input.py` (Повторный ввод)

Запрашивает целое число, пока пользователь не введёт положительное значение. После этого выводит его квадрат и количество неудачных попыток. Тип `int` гарантирован.

**Логика:**
- Цикл `while`: условие `chis <= 0`.
- В теле: ввод, увеличение счётчика попыток, если значение всё ещё не положительное — повтор.
- После выхода: `chis**2`.

**Проверки:**

| Ввод (по порядку) | Ожидаемый результат |
|-------------------|---------------------|
| 0, -2, 3 | Квадрат: 9, отклонено: 2 попытки |
| -10, -5, -1, 1 | Квадрат: 1, отклонено: 3 попытки |

### `variant.py` (Вариант 15: Числа, оканчивающиеся на 2 в записи модуля)

Условие: `abs(chis) % 10 == 2`.  
Программа запрашивает `n >= 0`, затем `n` целых чисел. Одним циклом находит количество и сумму таких чисел. Если подходящих нет — оба результата равны 0. Списки не используются.

**Контрольный набор (n = 7):** `-12, -3, 0, 2, 10, 15, 20`  
Подходящие: `-12` (|−12| % 10 = 2), `2` (2 % 10 = 2).  
Количество: 2, сумма: `-10`.

**Проверки:**

| Вход (n и числа) | Ожидаемый результат |
|------------------|---------------------|
| n=0 (без чисел) | Количество: 0, сумма: 0 |
| n=5: -2, 0, 3, 10, 20 | Количество: 1 (только -2), сумма: -2 |
| n=7: -12, -3, 0, 2, 10, 15, 20 | Количество: 2, сумма: -10 |
| Набор без подходящих (например, 1, 3, 5) | Количество: 0, сумма: 0 |

**Объяснение условия:** `abs(chis)` убирает знак, `% 10` даёт последнюю цифру. Так проверяется окончание на 2 независимо от знака.

## Пояснения по ключевым темам (для защиты работы)

- **Почему цикл завершается:** в `for` количество итераций задано явно через `range`; в `while` условие становится ложным из-за изменения переменной (или срабатывает `break`). В `positive_input.py` цикл завершается, когда `value > 0`. В проверке на простоту — когда `d * d > n`.
- **Почему `range(a, b)` не всегда соответствует условию задания №1:** `range` не включает верхнюю границу (`stop` не входит), и направление определяется только шагом. Поэтому для убывания нужен шаг `-1` и правильная верхняя граница (`b - 1`), а при равенстве `a == b` отдельный случай или диапазон длины 1.
- **Накопители и счётчики:** накопитель (например, `total`) хранит накопленное значение (сумму, произведение), счётчик (например, `count`) увеличивается на 1 при каждом подходящем событии. В `statistics.py` максимум нельзя инициализировать нулём — тогда он будет неверным для всех отрицательных чисел; нужно брать первое введённое значение.
