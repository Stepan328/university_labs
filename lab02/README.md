## Описание реализации и проверки

### `time_parts.py` (Перевод времени)

Программа вводит целое `total_seconds >= 0` и выводит количество полных часов, оставшихся минут и секунд. Используются операции `//` и `%`, без библиотек времени.

**Формулы:**
- Часы: `total_seconds // 3600`
- Минуты: `(total_seconds % 3600) // 60`
- Секунды: `total_seconds % 60`

**Проверки:**

| Вход | Ожидаемый результат |
|------|-------------------|
| 0 | 0 ч 0 мин 0 с |
| 59 | 0 ч 0 мин 59 с |
| 60 | 0 ч 1 мин 0 с |
| 3600 | 1 ч 0 мин 0 с |
| 3671 | 1 ч 1 мин 11 с |

---

### `purchase.py` (Стоимость покупки)

Программа вводит цену тетради `price >= 0` (целые рубли), количество `count >= 0` и переданную сумму `paid`. Гарантируется `paid >= price * count`. Выводится стоимость покупки и сдача.

**Формулы:**
- Стоимость: `price * count`
- Сдача: `paid - price * count`

**Проверки:**

| Вход | Ожидаемый результат |
|------|-------------------|
| 45, 3, 200 | Стоимость 135, сдача 65 |
| 45, 3, 135 | Стоимость 135, сдача 0 |
| 45, 0, 100 | Стоимость 0, сдача 100 |

---

### `variant.py` (Вариант 15: Порции на подносе)

Программа вводит два целых неотрицательных значения:
- `total` — общее количество порций.
- `capacity` — вместимость одного подноса (положительное число).

Вычисляет:
- Количество полностью заполнённых подносов: `total // capacity`
- Остаток порций: `total % capacity`
- Минимальное число подносов для размещения всех порций: `(total + capacity - 1) // capacity`
  - При `total = 0` результат равен 0.

Циклы и условия не используются — только арифметика.

**Проверки:**

| Вход | Полных подносов | Остаток | Всего подносов |
|------|-----------------|---------|----------------|
| 0, 10 | 0 | 0 | 0 |
| 20, 10 | 2 | 0 | 2 |
| 21, 10 | 2 | 1 | 3 |

**Дополнительные проверки:**
- `capacity = 1`: каждый поднос вмещает ровно одну порцию, полных подносов равно `total`, остаток 0.
- `total = capacity`: ровно один полный поднос, остаток 0, всего 1.

### Прогноз результатов выражений

До запуска Python вычислены вручную:

| Выражение | Прогноз | Результат Python | Совпадение |
|-----------|---------|------------------|------------|
| `2 + 3 * 4` | 14 | 14 | Да |
| `(2 + 3) * 4` | 20 | 20 | Да |
| `17 // 5` | 3 | 3 | Да |
| `17 % 5` | 2 | 2 | Да |
| `-7 // 2` | -4 | -4 | Да |

**Объяснение:**
- `2 + 3 * 4`: умножение выполняется раньше сложения, поэтому `3 * 4 = 12`, затем `2 + 12 = 14`.
- `(2 + 3) * 4`: скобки меняют приоритет, сначала `2 + 3 = 5`, затем `5 * 4 = 20`.
- `17 // 5`: деление с округлением вниз, `17 / 5 = 3.4`, целая часть — 3.
- `17 % 5`: остаток от деления, `17 = 3 * 5 + 2`, остаток 2.
- `-7 // 2`: деление с округлением вниз, `-7 / 2 = -3.5`, округление в меньшую сторону даёт -4 (не -3).

Результаты совпали с прогнозом — различий нет.

### `dopolnitelno.py` (Дополнительное задание)

Программа вводит положительный радиус `r` и вычисляет:
- Длину окружности: `2 * math.pi * r`
- Площадь круга: `math.pi * r ** 2`

Результат выводится с двумя знаками после запятой.

**Проверка:**
- Радиус 1: длина окружности `6.28`, площадь `3.14`.

## Пояснения по ключевым темам (для защиты работы)

- **Отличие `/` от `//`:** операция `/` всегда возвращает `float` (например, `7 / 2 = 3.5`), а `//` — целочисленное деление с округлением в меньшую сторону (`7 // 2 = 3`, `-7 // 2 = -4`).
- **Смысл остатка `%`:** для целых `a` и `b` при `b != 0` выполняется равенство `a == (a // b) * b + a % b`. Остаток показывает, сколько «не дотягивает» до следующего деления.
- **Почему форматирование не устраняет неточность `float`:** формат `:.2f` влияет только на отображение числа при выводе, но не меняет хранимое значение. Например, `0.1 + 0.2` хранится как `0.30000000000000004`, а `:.2f` покажет `0.30` — но само число внутри программы остаётся неточным. В денежных задачах лучше использовать целые рубли или копейки.
